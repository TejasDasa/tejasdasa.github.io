CUDA Transformer Runtime

A C++/CUDA transformer inference runtime, built operator by operator against a CPU reference, heading toward a paged KV-cache manager and multi-request scheduling.

status
stage 2 of 9: first CUDA operators
repo
github.com/TejasDasa/cuda-transformer-runtime

A transformer inference runtime in C++17 and CUDA, targeting compute capability 12.0, running the Stories15M checkpoint. The goal is to build it, understand its execution and memory behavior, then extend it with KV-cache management and scheduling. The distinctive part is measuring how memory layout and execution choices affect inference.

Every operation goes through the same loop: understand it, write a CPU reference, write the CUDA version, compare the results, then measure.

Where it is

Checkpoint loading. inspect_checkpoint memory-maps the model file rather than reading it. A 7-field header gives the model shape: dimension, hidden dimension, layers, attention heads, KV heads, vocabulary and maximum sequence length. The inspector rejects any shape that cannot be a valid model: heads that don’t divide the dimension, more KV heads than attention heads, an odd head size for RoPE. It then computes every weight tensor’s offset into the mapping: embeddings, per-layer attention and FFN weights (wq/wk/wv/wo, w1/w2/w3), RMSNorm weights, RoPE frequency tables and the classifier, which may share the embedding table. It checks that the expected size matches the file byte for byte before anything touches the weights.

Kernels. RMSNorm and matrix-vector multiply, each tested against its CPU version at 1e-5 relative plus 1e-5 absolute tolerance, on shapes that are not a multiple of the warp size (7 × 289).

__global__ void matvec_kernel(float* output, const float* matrix, const float* input, int rows, int cols)
{
    __shared__ float partial[32];

    int i = threadIdx.x;
    int row = blockIdx.x;
    int j = i;
    float local_sum = 0.0f;

    while (j < cols) {
        local_sum += matrix[row * cols + j] * input[j];
        j += blockDim.x;
    }
    partial[i] = local_sum;

    __syncthreads();

    int stride = 16;

    while (stride > 0) {
        if (i < stride) {
            partial[i] += partial[i + stride];
        }

        __syncthreads();
        stride = stride / 2;
    }

    if (i == 0) {
        output[row] = partial[0];
    }
}

One warp-sized block per output row, a strided partial dot product per thread, then a shared-memory tree reduction.

Milestones are correct text generation (stage 4), measured optimization (stage 6), then memory management and scheduling (stages 7–8).

The KV-cache manager is a cache-design problem in software: allocation granularity, logical-to-physical translation through the block table, locality and capacity, and how that layout interacts with the attention kernels that read it.
