RISC-V CPU

An RV32I core and bare-metal SoC in SystemVerilog: single-cycle and running a preemptive scheduler on a Zynq-7000 FPGA, with a five-stage pipeline in verification.

An RV32I processor and SoC written from scratch in SystemVerilog, with the software stack to run on it: startup code, drivers, trap handling and a preemptive round-robin scheduler, deployed on a Digilent Cora Z7-07S (Zynq XC7Z007S).
ISARV32I + Zicsr, machine mode: ECALL, MRET, precise traps and timer interrupts
Pipeline5-stage in-order: IF / ID / EX / MEM / WB
MemoryHarvard: separate instruction and data memories
SoCmemory-mapped bus, UART TX, machine timer, GPIO, interrupt controller
TargetDigilent Cora Z7-07S, Zynq-7000 programmable logic
Verificationunit and SoC testbenches, 31 regression programs, SVA, seeded random differential tests

Pipeline

    IF          ID          EX          MEM         WB
 PC → IMEM → IF/ID → Decode → ID/EX → ALU → EX/MEM → DMEM → MEM/WB
                     Regfile          Branch                Regfile
  • EX/MEM → EX and MEM/WB → EX forwarding, into the ALU, branch, JALR and store-data paths
  • WB → ID register bypass
  • One-cycle load-use stall: PC and IF/ID freeze, a bubble goes into ID/EX
  • Branches and jumps resolve in EX; a taken redirect flushes the younger instructions
  • Traps are precise. ECALL, illegal instructions and the machine timer interrupt all resolve in EX: the instruction there is flushed and recorded as mepc, fetch redirects to mtvec, and MRET re-executes it. The timer interrupt waveform below shows the whole sequence.
  • Zicsr is complete: CSRRW, CSRRS, CSRRC and their immediate forms, with CSRRS/CSRRC writing nothing when the source is x0. The CSR file holds mstatus, mie, mip, mtvec, mscratch, mepc, mcause and mtval; mstatus is WARL, with only MIE and MPIE writable and MPP reading as M-mode. Touching any other CSR raises an illegal-instruction trap in EX with no write-back.

Redirect priority in EX, from core.sv on the waveform-demos branch, where ex_trap covers both exceptions and interrupts:

always_comb begin
    ex_redirect    = 1'b0;
    ex_redirect_pc = 32'b0;

    // Priority: trap > mret > jalr > jal > branch.
    if (ex_trap) begin
        ex_redirect    = 1'b1;
        ex_redirect_pc = mtvec;
    end
    else if (ex_take_mret) begin
        ex_redirect    = 1'b1;
        ex_redirect_pc = mepc;
    end
    else if (ex_take_jalr) begin
        ex_redirect    = 1'b1;
        ex_redirect_pc = (ex_rs1_forwarded + id_ex_imm) & 32'hFFFF_FFFE;
    end
    else if (ex_take_jump) begin
        ex_redirect    = 1'b1;
        ex_redirect_pc = id_ex_pc + id_ex_imm;
    end
    else if (ex_take_branch) begin
        ex_redirect    = 1'b1;
        ex_redirect_pc = id_ex_pc + id_ex_imm;
    end
end

SoC and software

The core exposes a generic memory interface and knows nothing about peripherals; the bus decodes addresses to data memory, UART, timer and GPIO.

address
0x0000_0000instruction memory
0x0001_0000data memory
0x1000_0000UART TX data / +4 status
0x1000_0010timer count / compare / control

C and assembly build with the GNU RISC-V toolchain through a custom linker script and crt0, split into separate instruction and data images. The same images run in simulation and on the board.

On the FPGA

On the Cora Z7-07S the single-cycle SoC ran compiled C, drove the LEDs through GPIO, took periodic timer interrupts, and ran a preemptive round-robin scheduler: several tasks keeping their local state across repeated timer-driven context switches.

The board’s only UART is on the Zynq’s processing system, so the RV32I’s output crosses into it: an MMIO UART feeds a PL mailbox, a synchronized VALID/ACK handshake carries each byte across the clock domain to AXI GPIO, and Cortex-A9 firmware forwards it out through PS UART0 to the host.

These runs used the single-cycle version of the core. The pipelined core now takes traps and timer interrupts in simulation, and has not yet been revalidated on the board.

Verification

  • Unit and integration. Self-checking testbenches for every block from the ALU to the full SoC, and 31 assembly and C regression programs checked against expected output.
  • Retirement monitor. The core exposes retire_valid, retire_pc, retire_instr and the written register, so checking follows committed instructions independent of pipeline timing.
  • Assertions. x0 stays zero; invalid pipeline entries never change state or touch memory; load-use hazards stall the PC and inject a bubble; redirects flush younger instructions.
  • Random differential. A seeded generator emits RV32I programs biased toward back-to-back dependencies; they run on the RTL under Verilator and on an independent Python reference model, and all 32 registers are compared. ALU instructions today; loads, stores and branches are next.
